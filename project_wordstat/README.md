# Проект по автоматизации подбора ключевых фраз и проверки их в Wordstat

Данный проект представляет собой вспомогательный инструмент для автоматизации работы с ключевыми фразами информационных статей. Его основная задача — сократить объем ручной работы при подборе ключевых запросов и их проверке в сервисе статистики поисковых запросов Яндекс Wordstat.

В обычном рабочем процессе специалист сначала парсит сайт, с помощью Screaming Frog, и получает список страниц с заголовками и мета-данными. Далее вручную отбираются информационные статьи, и для каждой страницы формулируется ключевая фраза. После этого каждую фразу необходимо отдельно проверить в Wordstat, чтобы узнать ее частотность.

Этот процесс трудоемкий и занимает значительное количество времени. Разработанный инструмент решает сразу несколько задач:

- автоматически очищает и нормализует данные, полученные после парсинга сайта;
- автоматически фильтрует страницы и отделяет информационные материалы от нерелевантных;
- использует не только ручные правила, но и модель классификации страниц на статьи и не-статьи;
- автоматически определяет вероятные ключевые фразы на основе заголовков страниц;
- автоматически отправляет ключевые фразы в Wordstat и получает их частотность;
- формирует единый итоговый файл со всеми результатами.

Важно отметить, что полностью автоматическое и идеальное определение ключевой фразы по универсальным правилам невозможно. Структура сайтов, формулировки заголовков и смысл страниц различаются. Поэтому разработанное решение не заменяет специалиста, а выступает вспомогательным инструментом, который ускоряет работу и уменьшает объем ручных операций.

Дополнительно в проект встроена модель классификации, которая определяет, является ли страница статьей или нет. Она не заменяет правила, а дополняет их: помогает находить спорные случаи и уменьшает риск пропуска полезных материалов. Благодаря этому итоговая выборка становится более полной.

## Состав проекта

В папке проекта находятся следующие файлы и папки:

- `requirements.txt`
- `model.ipynb`
- `train_dataset_combined_with_target.csv`
- `fitstars.csv`
- `model_artifacts/`
- `project_wordstat_reordered_model_merge_exact_keyfix.ipynb`
- `wordstat_results_fitstars_ru.xlsx`

### requirements.txt
Файл со списком используемых библиотек, необходимых для запуска проекта в новом окружении. Он нужен для быстрой установки зависимостей.

### model.ipynb
Ноутбук, посвященный обучению и анализу модели классификации страниц. В нем выполняются:
- загрузка и исследование обучающей выборки;
- базовый EDA;
- подготовка текстовых признаков;
- обучение модели классификации;
- оценка качества модели;
- подбор рабочего порога классификации;
- сохранение артефактов модели для дальнейшего использования в основном проекте.

### train_dataset_combined_with_target.csv
Обучающая выборка для модели классификации. В файле содержатся размеченные страницы, на которых обучается модель определять, является страница статьей или нет.

### fitstars.csv
Исходный файл с данными, полученными после парсинга сайта. Обычно содержит URL страниц, `Title`, `H1` и другие поля, на основе которых ноутбук отбирает информационные статьи и формирует ключевые фразы. Этот файл присутствует в папке проекта как пример входных данных.

### model_artifacts
Папка с сохраненными артефактами модели. Она используется основным ноутбуком для подключения уже обученной модели без повторного обучения.

Обычно в ней находятся:
- `article_selector_logreg.joblib` — обученная модель классификации;
- `article_selector_tfidf.joblib` — TF-IDF-векторизатор;
- `article_selector_threshold.joblib` — выбранный порог классификации;
- `threshold_metrics.csv` — таблица метрик по разным порогам;
- `eval_test_predictions.csv` — предсказания модели на тестовой выборке.

### project_wordstat_reordered_model_merge_exact_keyfix.ipynb
Основной рабочий ноутбук проекта. В нем реализованы:
- загрузка и очистка исходной таблицы;
- нормализация данных;
- фильтрация страниц ручными правилами;
- подключение модели классификации на этапе отбора страниц;
- сравнение результатов правил и модели;
- объединение итогового набора страниц;
- автоматическое выделение ключевых фраз;
- подготовка запросов для Wordstat;
- получение частотности;
- сохранение итогового результата.

### wordstat_results_fitstars_ru.xlsx
Итоговый Excel-файл с результатами обработки. В нем сохраняются выбранные ключевые фразы, их статус обработки и частотности из Wordstat. Этот файл выступает основным результатом работы программы.

## Логика работы проекта

Проект работает по следующей схеме:

1. Загружается исходная таблица со страницами сайта.
2. Выполняется нормализация колонок и базовая очистка данных.
3. Страницы фильтруются по ручным правилам.
4. На этом же этапе подключается модель классификации, которая дополнительно оценивает, является ли страница статьей.
5. После анализа сводных таблиц формируется итоговый набор страниц:
   - включаются страницы, прошедшие ручные правила;
   - дополнительно могут включаться страницы, которые модель определила как статьи, а правила — нет.
6. Для итогового набора страниц формируются ключевые фразы.
7. Полученные ключи отправляются в Wordstat.
8. Результаты сохраняются в единый Excel-файл.

## Результат работы программы

На выходе система формирует единый Excel-файл, содержащий обработанные данные.

В нем представлены следующие основные столбцы:

### url
Адрес страницы, с которой была извлечена информация. Позволяет быстро перейти к исходной статье и проверить корректность выбранного ключа.

### title
Заголовок страницы, полученный при парсинге сайта.

### h1
Основной заголовок статьи, который часто наиболее точно отражает тему страницы и используется для генерации ключевой фразы.

### keyphrase
Автоматически определенная ключевая фраза. Обычно она формируется из `H1` или `Title` и дополнительно очищается от лишних элементов: служебных слов, пунктуации, хвостов после точки, вопросительного знака или тире.

### query_api
Фраза, которая отправляется в API Wordstat для проверки частотности. В большинстве случаев она совпадает с ключевой фразой.

### totalCount
Частотность запроса в Яндекс Wordstat. Этот показатель позволяет оценить, насколько часто пользователи ищут данную тему.

### status
Текущий статус обработки ключа.

Возможные значения:
- `pending` — ключ еще не отправлялся в Wordstat;
- `done` — частотность уже получена;
- `error` — при обработке произошла ошибка.

## Практическая ценность

Использование инструмента позволяет:

- существенно ускорить процесс подготовки ключевых фраз;
- снизить количество ручных действий при работе с Wordstat;
- систематизировать результаты в одном файле;
- использовать модель как дополнительный механизм проверки страниц;
- постепенно накапливать и обновлять данные по ключевым запросам.

Таким образом, разработанный сервис выполняет роль интеллектуального помощника специалиста по SEO-аналитике: он автоматизирует рутинные операции, дополняет ручные правила моделью классификации и оставляет человеку финальный контроль над выбором ключевых фраз.
